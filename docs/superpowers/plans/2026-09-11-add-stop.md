# Add Stop (Multi-Stop Booking) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a customer add up to N extra drop points to an order at booking time (N admin-configurable), priced at full multi-leg route distance plus a flat admin-configurable charge per stop, with the stop list visible read-only to admin and driver.

**Architecture:** One new, standalone `pkg_order_stops` table (zero changes to `pkg_order`'s existing columns — avoids the schema-drift risk already documented in the Next Day Booking feature). Two new admin-configurable values ride the backend's existing generic `app_settings` key-value mechanism (zero new endpoints/UI). The stops surcharge is folded into the existing `extra_mile_charge` column so it survives the driver-accept-time fare recomputation without touching `pricingEngine.js`'s formula or `tripLifecycle.js` at all.

**Tech Stack:** Node/Express/Prisma (MySQL) backend, React admin frontend, Flutter customer app (`ShifterOnline`). No driver-app (`ShifterDriver`) changes in this feature.

**Spec:** `docs/superpowers/specs/2026-09-11-add-stop-design.md`

## Global Constraints

- Zero changes to `pkg_order`'s existing columns — the new table (`pkg_order_stops`) carries all stop data.
- `dispatchManager.js` and `tripLifecycle.js` are not modified — the stops surcharge must reach driver-accept-time pricing purely through the existing `extra_mile_charge` column both already read.
- No new admin API endpoint or new admin settings UI component — `max_extra_stops`/`extra_stop_charge` ride the existing `app_settings`/`flags` mechanism in `settingsController.js` + `Settings.jsx`, unmodified.
- No driver-app (`ShifterDriver`) changes at all in this feature.
- `ShifterOnline/` (Flutter) is git-ignored in this repo (confirmed via `git log`: "stop tracking mobile app source trees, keep them local only") — its task's deliverable is the verified file edit, not a commit.
- No new npm/pub dependencies anywhere.
- A zero-stops order (the overwhelming majority of traffic) must behave byte-for-byte identically to today — every new code path is gated behind `stops` being a non-empty array.

```javascript
/**
 * Total route distance/duration across an ordered sequence of points
 * (pickup, extra stop(s), final drop) — sums each consecutive leg via the
 * existing two-point getRoadDistanceKm (which already falls back to
 * haversine per-leg on any Google API failure), rather than a single
 * pickup->drop call. `source` is "google" only if every leg used Google;
 * any haversine-fallback leg makes the whole result "mixed" so callers
 * can tell the total isn't uniformly road-distance-accurate.
 */
async function getMultiStopDistanceKm(points) {
  const legs = await Promise.all(
    points.slice(0, -1).map((point, i) =>
      getRoadDistanceKm(Number(point.lat), Number(point.lng), Number(points[i + 1].lat), Number(points[i + 1].lng))
    )
  );
  return {
    distanceKm: legs.reduce((sum, leg) => sum + leg.distanceKm, 0),
    durationMin: legs.reduce((sum, leg) => sum + leg.durationMin, 0),
    source: legs.every((leg) => leg.source === "google") ? "google" : "mixed",
  };
}
```

```javascript
// Admin-configurable via the existing generic app_settings/flags mechanism
// (settingsController.js's updateSettings already upserts any key into
// this table with no allowlist, and Settings.jsx already renders every
// key present in `flags` as an editable field) — no new endpoint or admin
// UI component needed for these two settings.
async function getAddStopSettings() {
  const rows = await prisma.app_settings.findMany({
    where: { setting_key: { in: ["max_extra_stops", "extra_stop_charge"] } },
  });
  const map = Object.fromEntries(rows.map((r) => [r.setting_key, r.setting_value]));

  const parsedMax = Number(map.max_extra_stops);
  const parsedCharge = Number(map.extra_stop_charge);

  return {
    maxExtraStops: Number.isFinite(parsedMax) ? parsedMax : 2,
    extraStopCharge: Number.isFinite(parsedCharge) ? parsedCharge : 0,
  };
}
```
